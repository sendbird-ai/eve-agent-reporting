# Security reporting

Do not put credentials, tenant identifiers, production payloads, or exploitable
private-system details into a public issue or pull request.

Use GitHub private vulnerability reporting when enabled. If it is unavailable,
ask a maintainer for a private reporting route without disclosing the vulnerability
in public. A private route must be confirmed before sending sensitive evidence.

Include the affected released version, impact, a minimal synthetic reproduction,
and any mitigation. Report findings in consumer deployments to their owners through
their private reporting process.

The current implementation is undergoing a neutrality/compatibility migration.
Repository policy is not a security certification. Supported release versions and
response commitments will be documented with the first approved clean baseline;
do not assume an unpublished candidate has support guarantees.
